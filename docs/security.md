# Security review before mainnet

Review of every API route, the admin surface, headers, cookies, outbound fetches, uploads, the keeper's swap and key handling, SQL, dependencies and the client bundle. Each finding has a severity and either the fix (with the commit that made it) or the risk we accept and why.

Severity: high (loss of funds or admin takeover), medium (abuse that costs money, integrity of public data, or a likely path to a high), low (hardening), info (checked, nothing to change).

## Findings

| # | Area | Severity | Finding | Status |
|---|---|---|---|---|
| 1 | Admin sign in | high | Admin rested on wallet message signing plus an `ADMIN_WALLETS` list; a session was a stateless JWT that could not be revoked before its 8 hour expiry. | Fixed: access code login (below). |
| 2 | Admin API | medium | Admin routes relied on SameSite=Strict alone against cross site requests. | Fixed: every admin route checks Origin (required on writes) and Sec-Fetch-Site. |
| 3 | Votes | medium | `/api/token/[mint]/vote` took an unsigned `wallet` field as the voter id, so anyone could vote as any wallet, or as a new random wallet per request. Reading took `?wallet=` too, so anyone could read any wallet's vote. | Fixed: the anonymous `quants_voter` cookie is the only voter id. Accepted: a client that clears cookies can vote again; votes are an admin signal only, never shown publicly, and posting is rate limited (30 a minute per address). |
| 4 | Rate limits | medium | `/api/launch/confirm` (two RPC calls per request) and the public read routes (chart, explore, launches, live, traders, trades, rewards) had no rate limit. | Fixed: per address limits on all of them (confirm 20 a minute, reads 120 to 240). `/api/health` stays open for the container health check. |
| 5 | Launch content | medium | `/api/launch/prepare` accepted any https metadata URI and image, so a launch made through the API could show content never uploaded through quants. | Fixed: with Cloudinary set (production), both must start with `https://res.cloudinary.com/<our cloud>/`. |
| 6 | Keeper key | medium | `loadKeypair` let a JSON parse error through, and Bun's parse errors quote the text they failed on, which would put part of the secret key in the logs. | Fixed: a fixed error message. Keypairs reach only the keeper container, as read only Docker secrets (`/run/secrets/keeper`, `/run/secrets/spill`), never the env file, image or web container. Nothing logs env values. |
| 7 | Headers | low | No HSTS, Permissions-Policy or COOP; `X-Powered-By` was sent. | Fixed: HSTS (2 years, production only, also set by Caddy), `Permissions-Policy` denying camera, microphone, geolocation, payment and USB, `Cross-Origin-Opener-Policy: same-origin-allow-popups` (wallet popups keep working), `upgrade-insecure-requests` in production, `poweredByHeader: false`. |
| 8 | CSP | low | `script-src` allows `'unsafe-inline'`, which the App Router needs for its inline hydration scripts without per request nonces. | Accepted: there is no HTML injection point (no `dangerouslySetInnerHTML`, React escapes all user text, links are https only), `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'`. Nonces through a proxy are the follow up if a sink ever appears. |
| 9 | Admin cookie | low | Cookie name without a prefix. | Fixed: `__Host-quants_admin` in production (browser enforces Secure, Path=/, no Domain). |
| 10 | Outbound fetch | low | `token-live` put the mint from the URL into the Jupiter search query unencoded. The host is fixed, so not SSRF, but a crafted mint could add query parameters. | Fixed: `encodeURIComponent`. |
| 11 | Outbound fetch (SSRF) | info | Every server side fetch goes to a fixed host: Jupiter, DexScreener, Cloudinary, xStocks, Backpack, the RPC. Token images are shown by the browser through the wsrv.nl resizer, never fetched by the server. The one admin set URL is the alert webhook, posted to by the keeper and indexer. | Accepted: the webhook must be https and only an admin can set it. |
| 12 | Uploads | info | `/api/metadata`: 2.3 MB body limit checked from Content-Length before reading (chunked bodies refused), Caddy caps bodies at 3 MB, PNG/JPEG/WebP only and the bytes must match the declared type (an SVG labelled PNG is refused), square only, 10 a minute per address. Cloudinary public ids are content hashes with `overwrite=false`, so one upload can never replace another. The API secret is server side only. | No change. |
| 13 | Jupiter swaps | medium | The keeper signs Jupiter built transactions. `assertSafeSwap` refuses any program other than Jupiter, compute budget, the token programs and associated token, allows only wrapping the keeper's own SOL and closing to the keeper, and requires the keeper as fee payer. The Jupiter route instruction itself is not decoded: a compromised Jupiter API could route output to another account. | Accepted: the API is reached over TLS with our key; each swap moves only that step's basket or rent amount; the keeper reconciles the ledger against its wallets every run and stops (with an alert) on any shortfall, so a diverted swap halts payouts instead of repeating. |
| 14 | DAMM adapter (devnet) | info | The devnet swap adapter allows only DAMM v2 swaps on the configured stand-in pools into the keeper's own accounts, plus compute budget and the keeper's token account plumbing. | No change; it is not used on mainnet. |
| 15 | SQL injection | info | All queries are Bun SQL tagged templates. The one `sql.unsafe` in app code (`landing.ts`) inserts an ORDER BY clause looked up from a constant map by a zod enum; migrations run files from the repo. | No change. |
| 16 | Error leakage | info | Unknown errors return `{"code":"internal","message":"Something went wrong. Try again."}` with a 500 and are logged server side; only `LaunchError`, `AuthError`, `LimitError` and zod messages reach clients, and those are written for users. | No change. |
| 17 | Server actions | info | There are none (no `"use server"`). | No change. |
| 18 | Client bundle | info | Fetched every script that `/`, `/launch`, `/explore`, `/docs`, `/portfolio`, `/rewards`, `/terms` and the `/admin` 404 load (23 scripts, rechecked on the dev server after the admin moved) and searched them for `whitehouse`, `kremlin` and the admin UI strings (none found), and earlier and searched them for the values of `ADMIN_SESSION_SECRET`, `KEEPER_KEYPAIR`, `SPILL_KEYPAIR`, `DATABASE_URL` and for the names of every server secret. The only hit is the admin Wallets tab text naming `PLATFORM_ADDRESSES`, which holds public addresses. The browser only gets `NEXT_PUBLIC_RPC_URL` (use a domain restricted key) and `NEXT_PUBLIC_X_URL`. `next.config.ts` refuses to build with the test wallet and a non local RPC. | No change. |
| 19 | Dependencies | medium | `bun audit`: bigint-buffer (high, buffer overflow in `toBigIntLE`), toml (two highs, recursion and prototype pollution), stream-json (moderate, DoS) and uuid (moderate). All are transitive through @solana/web3.js, @solana/spl-token and Anchor in the Meteora and Kamino SDKs. | Accepted for launch: bigint-buffer parses account data from our own RPC, toml is only used by Anchor to read a workspace `Anchor.toml` (never called here), stream-json sits in the RPC client parsing our RPC's responses, and quants never passes a buffer to uuid. Revisit when the SDKs move to @solana/kit. |
| 20 | Stake and trade builders | info | `/api/stake/*`, `/api/trade/*` and the first buy swap build unsigned transactions for the address in the request; the user's wallet signs, so a wrong address only produces a transaction its owner never signs. Addresses are validated as base58. | No change. |
| 21 | Prepare abuse | info | Prepare is unauthenticated and writes a `prepared_launches` row per call (rate limited to 20 a minute; rows unconfirmed after a day are deleted by the keeper). Config key claims are bounded by pairs times fee tiers at the current targets, and a claim costs us nothing until a launcher pays to create it. A pending config address found on chain with any other fee claimer, mint or threshold is dropped, not used. | No change. |
| 22 | Keeper top up | info | While the keeper holds under 0.01 SOL, prepare adds a transfer from the launcher to the keeper of at most 0.01 SOL. The balance is read server side (20 second cache) and nothing is added once the keeper is funded. | No change. |
| 23 | Admin discovery | low | The admin sat at `/admin` and its API at `/api/admin/*`, the first paths a scanner tries; `/api/admin/settings` answered 401, which confirmed an admin exists. | Fixed: the admin is served at `/whitehouse` and `/kremlin` with its API under `/api/whitehouse/`. `/admin` and every `/api/admin/*` path are plain 404s, nothing links to the admin, its page is `noindex`, and the page view counter ignores it. The paths are not in any public script (checked below). Obscurity is not the control; the session checks are. |
| 24 | Admin page render | low | The admin page rendered the pair list into its HTML before sign in. | Fixed: the page renders only the sign in shell; the pair rows come with the settings response after sign in. Checked: the `/whitehouse` HTML has no settings values. |
| 25 | Admin 401 detail | low | A forged cookie and an ended session got different messages ("Sign in first" and "Session ended"). | Fixed: every 401 is the same body, `Sign in first`, whether the cookie is missing, forged, truncated, expired, revoked or from before a code rotation. |
| 26 | Read only access | info | Read only codes (see below) must never change state or see secrets. | Every write handler (POST, PUT, PATCH, DELETE) under `/api/whitehouse` calls `requireAdmin(..., "full")` before reading its body and answers 403 to a read only session. `tests/web/admin-roles.test.ts` walks every route file in that folder, so a new route without the check fails the suite. Read only responses leave out wallet derivation paths and the alert webhook URL. |
| 27 | Admin caching | low | Admin API responses had no `Cache-Control`. | Fixed: `no-store` on every admin API response and on the sign in response. The admin page is dynamic, which Next serves `no-store` already. |

## Admin access code

Checked again in the admin pass (read only codes, unlisted paths): every item below holds for both kinds of code.

- The code is 24 characters from `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (120 bits), made by `scripts/admin-code.ts`, written to `~/.config/quants/<cluster>/admin-code.txt` mode 600. The server holds only an argon2id hash (19 MiB, 2 passes) in `ADMIN_CODE_HASH`, base64 encoded so `$` survives env files and compose interpolation, and refuses to start without it.
- Checked with `Bun.password.verify` (constant time). Inputs over 64 characters are refused before hashing; one check runs at a time so a burst cannot exhaust memory.
- 5 wrong codes per address per 15 minutes, 50 wrong codes per hour in total, then sign in is refused for the rest of the window. Attempts are rows in `admin_logins` (kept 7 days) and log lines. Behind Caddy the address comes from `X-Forwarded-For`, which Caddy sets itself (it does not trust a client supplied one), and only with `TRUST_PROXY=1`.
- The session is a random 32 byte token: the cookie carries it with an HMAC from `ADMIN_SESSION_SECRET`; the database stores only its sha256, the creating address, a 12 hour expiry, a revoked time and a fingerprint of the code hash. Sign out revokes the row. Rotating the code changes the fingerprint and ends every session.
- Cookie: httpOnly, SameSite=Strict, Path=/, Secure and `__Host-` prefixed in production, Max-Age 12 hours. A test signs in with `NODE_ENV=production` and checks each flag, and that the unprefixed name is refused there.
- Every admin route checks Origin (required on writes, must equal `SITE_URL`) and refuses any `Sec-Fetch-Site` other than `same-origin` or `none`, before the session.
- Read only codes are made by the full admin, 24 characters like the full code, shown once and stored only as argon2id PHC strings in `admin_codes`. Sign in checks the full code first, then each live read only code (at most 10), all inside the one at a time lock and the same lockout counters. A session row records `role` and, for read only, `code_id`; the session check requires the code to be unrevoked in the same query, and revoking also marks its sessions revoked, so revoking takes effect on the next request. Rotating `ADMIN_CODE_HASH` still ends every session of both kinds.
